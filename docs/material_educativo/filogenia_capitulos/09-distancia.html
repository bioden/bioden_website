Capítulo 9: Métodos de distancia (NJ, UPGMA, K2P)

9.1 ¿Qué son los métodos basados en distancia?

Los métodos basados en distancia transforman el alineamiento en una matriz de distancias pairwise (n×n, donde n es el número de secuencias) y construyen el árbol a partir de esa matriz, en lugar de usar el alineamiento directamente.

El pipeline es:

  1. Calcular distancias pairwise entre todas las parejas de secuencias (corregidas por un modelo de sustitución).
  2. Construir el árbol con un algoritmo de clustering (NJ, UPGMA, minimum evolution).
Note

Estos métodos son rápidos (escalan como O(n²) o O(n³)) y por eso se usan como primer árbol exploratorio o en datasets masivos donde ML es prohibitivo. La contrapartida es que no optimizan verosimilitud: pueden dar topologías subóptimas respecto a ML/Bayesiano en datos difíciles.

9.2 Construcción de la matriz de distancias

Para n secuencias se calculan n(n-1)/2 distancias pairwise. Cada distancia d_ij se obtiene contando las diferencias entre las secuencias i y j y corrigiendo por múltiples sustituciones usando un modelo.

9.3 Modelos de distancia comunes

9.3.1 p-distance

La proporción simple de sitios distintos entre dos secuencias:

p = D / L

donde D = número de sitios distintos, L = longitud del alineamiento. No corrige múltiples sustituciones. Subestima la distancia real cuando p > 0.1. Solo válida para secuencias muy cercanas.

9.3.2 Jukes-Cantor

Corrige la p-distance con el modelo JC69:

d = -(3/4) · ln(1 - (4/3) · p)

9.3.3 Kimura 2-parameters (K2P)

Distingue transiciones (P) de transversiones (Q):

d = -(1/2) · ln(1 - 2P - Q) - (1/4) · ln(1 - 2Q)

Es el estándar para DNA barcoding (COI) y para árboles exploratorios de ADN.

9.3.4 Tamura-Nei (TN93)

Como K2P pero permite frecuencias desiguales y dos clases de transición distintas. Mejor para datos sesgados.

9.3.5 LogDet

Útil cuando la composición de nucleótidos varía mucho entre secuencias (p. ej. entre genomas con GC muy distinto). No asume estacionariedad.

9.3.6 GTR

La distancia GTR usa el modelo general reversible. Equivalente a lo que haría ML con GTR+Γ, pero en versión pairwise.

9.4 Distancias para proteínas

  • p-distance: simple fracción de sitios distintos.
  • Poisson: corrige como en JC69 pero para 20 estados.
  • Kimura (proteína): modelo de Kimura 1983 para aminoácidos, considera la composición.
Tip

Para árboles exploratorios de proteínas, la distancia Poisson es razonable. Para distancias más precisas se usan distancias basadas en matrices empíricas (p. ej. Score=−ln(probabilidad según BLOSUM62), pero esto requiere programas especializados).

9.5 Cálculo de distancia con BioPython

from Bio import AlignIO
from Bio.Phylo.TreeConstruction import DistanceCalculator

# Cargar alineamiento
aln = AlignIO.read("cytb_aln.fasta", "fasta")

# Calcular matriz de distancias
calculator = DistanceCalculator('k2p')   # modelo K2P
dm = calculator.get_distance(aln)
print(dm)

9.6 Algoritmos de clustering

9.6.1 UPGMA (Unweighted Pair Group Method with Arithmetic Mean)

Asume reloj molecular estricto: las tasas de evolución son iguales en todas las ramas. Construye un árbol ultramétrico (todas las hojas equidistantes de la raíz).

Funciona bien cuando:

  • El reloj molecular es razonable (p. ej. datos recientes dentro de una especie).
  • Distancias cortas.

Falla cuando hay tasas heterogéneas entre linajes (lo normal en datos reales): produce agrupaciones artefactuales por long-branch attraction.

9.6.2 Neighbor-Joining (NJ) (Saitou & Nei 1987)

No asume reloj molecular. Optimiza la longitud total del árbol:

S(T) = Σ d_ij (sobre todas las ramas)

Es el método más usado para árboles de distancia. Equivalente a minimum evolution bajo ciertas condiciones. La implementación de Studier & Keppler (1988) es la más conocida.

9.6.3 Minimum Evolution (ME)

Variante que busca minimizar Σ(longitudes de rama). NJ es un caso especial heurístico.

9.6.4 BIONJ (Gascuel 1997)

Mejora de NJ que usa la covarianza entre distancias (las distancias comparten caminos). Suele dar mejores árboles que NJ clásico en datos con saturación.

9.7 QuickTree: NJ rápido para datasets grandes

conda install -c bioconda quicktree -y

# Árbol NJ con corrección Kimura
quicktree -in mafft -i aln.fasta -out tree.nwk -kimura

# Sin corrección (p-distance)
quicktree -in mafft -i aln.fasta -out tree.nwk

Útil cuando tienes miles de secuencias y necesitas un árbol rápido.

9.8 PHYLIP: clásico pero vigente

conda install -c bioconda phylip -y

# Paso 1: matriz de distancias
# dnadist lee PHYLIP secuencial o intercalado
echo "10 1140" > aln.phy          # encabezado PHYLIP
cat aln_body.txt >> aln.phy
dnadist -infile aln.phy -outfile out.dist -method k  # k = Kimura

# Paso 2: árbol NJ desde matriz
neighbor -infile out.dist -outfile tree.nwk -outgroupout -method n
# -method n = Neighbor-Joining
# -method u = UPGMA

# Opciones adicionales
neighbor -infile out.dist -outfile tree.nwk -method n -jumble 100 -trout
# -jumble 100: 100 ordenes aleatorios de entrada
# -trout: escribir árbol en formato Newick
Warning

PHYLIP es interactivo: si no se proveen flags, lanza un menú. Para scripts, siempre pasa todos los flags y redirige la entrada. Usa printf "Y\n" | neighbor ... para responder al prompt final.

9.9 BioPython para NJ

from Bio import AlignIO
from Bio.Phylo.TreeConstruction import DistanceCalculator, DistanceTreeConstructor
from Bio.Phylo import draw

# Cargar alineamiento
aln = AlignIO.read("cytb_aln.fasta", "fasta")

# Matriz de distancias
calculator = DistanceCalculator('k2p')
dm = calculator.get_distance(aln)

# Árbol NJ
constructor = DistanceTreeConstructor()
nj_tree = constructor.nj(dm)
upgma_tree = constructor.upgma(dm)

# Guardar
from Bio import Phylo
Phylo.write(nj_tree, "nj.nwk", "newick")
Phylo.write(upgma_tree, "upgma.nwk", "newick")

# Visualizar
Phylo.draw_ascii(nj_tree)

9.10 Herramientas modernas

  • IQ-TREE puede construir árboles NJ vía distancias pairwise (con bootstrap ultra-rápido):
# Distancias y árbol NJ con bootstrap UF
iqtree2 -s aln.fasta -m K2P -n 0 -B 1000 -pre nj_iqtree -alrt 0
# -n 0: no buscar ML, solo árbol inicial NJ
  • FastTree (Price et al. 2010): NJ aproximado modificado con bootstrap SH-like. Para datasets masivos (>10000 secuencias):
conda install -c bioconda fasttree -y

# ADN con GTR+Gamma
FastTree -nt -gtr aln.fasta > tree.nwk

# Proteína con LG+Gamma
FastTree -lg protein_aln.fasta > tree.nwk
Tip

FastTree se ve en detalle en el capítulo 12. Es la opción por excelencia para alineamientos masivos (rRNA de microbiomas, miles de genomas virales, etc.).

9.11 Soporte de ramas en NJ

NJ por sí mismo no da valores de soporte. Para cuantificar la robustez de cada clado:

  • Bootstrap clásico (Felsenstein): re-muestrea columnas del alineamiento con reemplazo y reconstruye el árbol, contando cuántas veces cada clado aparece. Típicamente 1000 replicados.
  • IQ-TREE UFBootstrap: bootstrap ultra-rápido (~10× más rápido).
# Bootstrap clásico con PHYLIP (lento)
seqboot -infile aln.phy -outfile boot.phy -reps 100
# luego para cada réplica: dnadist + neighbor + consense

# IQ-TREE UFBootstrap
iqtree2 -s aln.fasta -m K2P -B 1000 -pre nj_boot

9.12 Limitaciones de NJ

  • No optimiza verosimilitud: puede dar topologías subóptimas respecto a ML en datos difíciles.
  • Asume distancias aditivas: si las distancias están saturadas, NJ se equivoca.
  • Sensibilidad a secuencias outlier: una secuencia muy divergente puede romper el árbol (se atrae a la siguiente más larga).
  • No aprovecha información de sitios: solo usa la matriz de distancias, perdiendo la señal columna-a-columna que usan ML y parsimonia.
Important

Uso recomendado: NJ es excelente para árboles preliminares, exploración rápida, datasets masivos o verificación de la homogeneidad de los datos. No es adecuado como método final en publicaciones cuando se dispone de tiempo de cómputo para ML o Bayesiano.

9.13 Distancias K2P para DNA barcoding

El Consortium for the Barcode of Life (CBOL) estableció K2P como estándar para DNA barcoding de COI. Permite:

  1. Calcular distancia intra-específica: variación dentro de una especie.
  2. Calcular distancia inter-específica: distancia mínima a otras especies del género.
  3. Identificar “barcode gap”: hueco entre las dos distribuciones. Si existe, las especies son identificables; si no, el barcoding falla.
# Calcular matriz K2P con MEGA CLI (si instalado) o BioPython
# O con PHYLIP dnadist -method k
# Calcular distancia intra vs inter con BioPython
from Bio import AlignIO
from Bio.Phylo.TreeConstruction import DistanceCalculator

aln = AlignIO.read("coi.fasta", "fasta")
calculator = DistanceCalculator('k2p')
dm = calculator.get_distance(aln)

# Distancia intra vs inter (asumiendo nombres con prefijo especie)
from collections import defaultdict
intra, inter = [], []
names = dm.names
for i, ni in enumerate(names):
    for j in range(i+1, len(names)):
        nj = names[j]
        sp_i = ni.split("_")[0]
        sp_j = nj.split("_")[0]
        d = dm[ni, nj]
        if sp_i == sp_j:
            intra.append(d)
        else:
            inter.append(d)

print(f"Intra: mean={sum(intra)/len(intra):.4f}, max={max(intra):.4f}")
print(f"Inter: mean={sum(inter)/len(inter):.4f}, min={min(inter):.4f}")

9.17 Ejemplo completo: NJ de 30 primates basado en Cytochrome b

# 1. Alinear
mafft --auto primates_cytb.fasta > cytb_aln.fasta

# 2. Recortar
trimal -in cytb_aln.fasta -out cytb_trim.fasta -automated1

# 3. Convertir a PHYLIP
seqkit seq cytb_trim.fasta --phylip > cytb.phy
# Editar encabezado: número de secuencias y longitud
# (seqkit genera formato phylip-relaxed; dnadist prefiere estándar)

# 4. Matriz de distancias con dnadist (Kimura)
printf "K\nY\n" | dnadist -infile cytb.phy -outfile cytb.dist

# 5. Árbol NJ
printf "N\nY\n" | neighbor -infile cytb.dist -outfile cytb.nj.tree -outtreefile cytb.nj.nwk

# 6. Visualizar ASCII
python3 -c "from Bio import Phylo; Phylo.draw_ascii(Phylo.read('cytb.nj.nwk','newick'))"

Solución 2

# Construir ambos árboles sobre el mismo dataset
# NJ
printf "N\nY\n" | neighbor -infile cytb.dist -outfile cytb.nj.out -outtreefile cytb.nj.nwk

# UPGMA
printf "U\nY\n" | neighbor -infile cytb.dist -outfile cytb.upgma.out -outtreefile cytb.upgma.nwk

# Comparación: ¿cuál es ultramétrico?
# Ultramétrico = todas las hojas a la misma distancia de la raíz.
# Verificar: en árbol ultramétrico, suma de longitudes de rama raíz→cualquier hoja es constante.

python3 << 'EOF'
from Bio import Phylo

for label, fname in [("NJ", "cytb.nj.nwk"), ("UPGMA", "cytb.upgma.nwk")]:
    tree = Phylo.read(fname, "newick")
    depths = {}
    for clade in tree.get_terminals():
        depths[clade.name] = tree.distance(clade)
    vals = list(depths.values())
    span = max(vals) - min(vals)
    print(f"{label}: profundidad min={min(vals):.4f} max={max(vals):.4f} span={span:.4f}")
    print(f"  -> {'ULTRAMÉTRICO' if span < 1e-4 else 'NO ultramétrico'}")
EOF
NJ:    profundidad min=0.0823 max=0.2321 span=0.1498
  -> NO ultramétrico
UPGMA: profundidad min=0.1567 max=0.1567 span=0.0000
  -> ULTRAMÉTRICO

Análisis:

  1. UPGMA es ultramétrico: todas las hojas están a la misma distancia de la raíz. Esto refleja la asunción de reloj molecular estricto. Asume que todos los linajes evolucionan a la misma tasa.
  2. NJ no es ultramétrico: las longitudes de rama reflejan tasas distintas por linaje. Mus y Rattus (roedores) tienen ramas largas (tasa acelerada, típica en roedores), mientras que primates tienen ramas más cortas.
  3. ¿Cuál es más realista?: NJ. La biología comparada muestra que los roedores tienen tasas moleculares 2-4× superiores a primates (efecto de generación corta, metabolismo alto). Un árbol que ignora esto (UPGMA) agruparía artefactualmente los roedores con primates pequeños, rompiendo la topología esperada. NJ, al permitir tasas heterogéneas, recupera la separación Glires–Primates correctamente.
  4. Conclusión: UPGMA solo es apropiado para datos con reloj molecular verificable (p. ej. virus de evolución reciente o datos intraespecíficos con reloj calibrado). Para filogenia interespecífica casi siempre NJ (o mejor ML/Bayesiano) es preferible.

Solución 3

#!/usr/bin/env bash
# distancia_k2p.sh - Construye árbol NJ con bootstrap desde alineamiento PHYLIP
# Uso: distancia_k2p.sh aln.phy output_basename

set -euo pipefail

ALN="$1"
BASE="${2:-nj_out}"

if [[ ! -f "$ALN" ]]; then
    echo "Error: no existe el archivo $ALN"
    exit 1
fi

# 1. Matriz de distancias K2P original
echo "[1/4] Matriz de distancias K2P..."
printf "K\nY\n" | dnadist -infile "$ALN" -outfile "${BASE}.dist"
printf "N\nY\n" | neighbor -infile "${BASE}.dist" \
                          -outfile "${BASE}.nj.out" \
                          -outtreefile "${BASE}.nj.nwk"
echo "  -> Árbol NJ inicial: ${BASE}.nj.nwk"

# 2. Bootstrap: 1000 réplicas
echo "[2/4] Generando 1000 réplicas bootstrap..."
printf "S\nY\n" | seqboot -infile "$ALN" -outfile "${BASE}.boot" -replicates 1000 -datatype d

# 3. Matriz de distancias para cada réplica
echo "[3/4] Matrices K2P por réplica..."
printf "K\n100\nY\n" | dnadist -infile "${BASE}.boot" -outfile "${BASE}.boot.dist" -multidata

# 4. Árboles NJ por réplica
echo "[4/4] Árboles NJ por réplica..."
printf "N\n100\nY\n" | neighbor -infile "${BASE}.boot.dist" \
                                -outfile "${BASE}.boot.out" \
                                -outtreefile "${BASE}.boot.nwk" -multidata

# 5. Consenso strict (>50%)
printf "C\nY\n" | consense -intreefile "${BASE}.boot.nwk" \
                            -outfile "${BASE}.consensus.out" \
                            -outtreefile "${BASE}.consensus.nwk"

echo ""
echo "Listo:"
echo "  Árbol NJ (sin bootstrap):     ${BASE}.nj.nwk"
echo "  Árbol consenso (boot > 50%):  ${BASE}.consensus.nwk"
echo ""
echo "Visualización ASCII:"
python3 -c "from Bio import Phylo; Phylo.draw_ascii(Phylo.read('${BASE}.consensus.nwk','newick'))"
# Hacer ejecutable
chmod +x distancia_k2p.sh

# Probar con 20 secuencias
# Primero subconjunto de 20 secuencias del archivo completo
head -1 cytb.phy | awk '{print $1}' > n.txt  # número de secuencias original
# (en PHYLIP, las primeras líneas son 1 encabezado + n secuencias)
# Mejor: usar seqkit para reducir a 20 secuencias
seqkit head -n 20 cytb_trim.fasta > cytb_20.fasta
seqkit seq cytb_20.fasta --phylip > cytb_20.phy

# Ejecutar el script
./distancia_k2p.sh cytb_20.phy cytb_20
